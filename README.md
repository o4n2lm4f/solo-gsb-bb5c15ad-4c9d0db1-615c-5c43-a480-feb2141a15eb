# WebVTT 字幕时序修复器

一款**完全本地运行**的 WebVTT（`.vtt`）字幕时序修复工具。粘贴或导入字幕后，可以直接在时间轴上拖动片段及其边界，修复重叠、间隔过小、时长不足等问题。锁定片段不会被任何调整推动；当约束无解时，本次调整会被自动撤销，并在时间轴上标出冲突区间。

内置**两点同步批量校准**：选择两个按时间排序的未锁定锚点片段并分别输入新开始时间，由唯一线性映射整体校准闭区间内的全部未锁定片段；应用前时间轴以虚影预览并显示影响数量，存在冲突时禁止应用并完整列出，绝不部分写入。

内置**画面布局预览**：解析所选片段的 `line` / `position` / `size` / `align` 设置，在 16:9 预览区中显示字幕框与 10% 安全区；非法取值或字幕框超出安全区会进入问题清单，点击即可定位片段。四个布局字段提供独立编辑控件，修改时其它未知 cue 设置的原始顺序与内容完全保留。

技术栈：**React 18 + TypeScript + Vite**，纯前端，无后端，数据不离开浏览器。

## 一条命令启动（Docker Compose）

```bash
docker compose up --build
```

启动后用浏览器访问：

> **http://localhost:8080**

停止：`Ctrl+C`；后台运行：`docker compose up --build -d`；停止并移除容器：`docker compose down`。

如 8080 端口被占用，修改 `docker-compose.yml` 中的 `"8080:80"`（例如 `"9090:80"`）即可。

## 本地开发（无需 Docker）

```bash
npm install
npm run dev        # 开发服务器，访问 http://localhost:5173
npm run build      # 类型检查 + 生产构建到 dist/
npm run preview    # 本地预览生产构建
npm test           # 运行求解器/解析器逻辑测试（无需浏览器）
```

## 使用方法

1. **导入字幕**：点击右上角「粘贴 / 导入」，选择 `.vtt` 文件，或直接粘贴 WebVTT 文本后「解析并载入」。首次打开会自动载入一份带问题的示例字幕。
2. **在时间轴上调整**：
   - 拖动片段**中部**：整体平移（保持时长）；
   - 拖动片段**左/右边缘**：修改开始/结束时间（改变时长）；
   - 滚轮区域上方有「－ / ＋ / 适应窗口」可缩放时间轴，也可横向滚动。
3. **锁定片段**：点击列表中的 🔓，或在右侧检查器勾选「锁定」。锁定片段在任何拖动传播中**绝不移动或改变时长**。
4. **约束设置**（右侧栏）：
   - **最小片段时长**：任何片段（含被传播压缩的片段）不得短于该值；
   - **相邻片段间隔**：相邻片段之间至少保留的间隔。
5. **冲突传播规则**：
   - 向右拖动时，压力按操作方向**向右传播**：后续片段先整体平移，撞到锁定片段时再从近到远收缩到最小时长；
   - 向左拖动为镜像过程，边界为锁定片段或时间轴起点 `00:00.000`；
   - 传播后仍无法满足全部约束时，调整**自动撤销**，红色斜纹标出冲突区间，并在时间轴下方显示原因横幅；
   - 再次开始拖动或手动编辑后，冲突标记自动清除，也可点击「消除标记」。
6. **实时反馈**：
   - 时间轴上红色斜纹 = 重叠/非法时间（错误），黄色虚线斜纹 = 间隔不足/时长不足（警告）；
   - 右侧「问题清单」列出全部问题（含布局问题），点击任一问题会选中并滚动到对应片段；
   - 悬停片段可在底部查看精确时间码与时长，拖动时有跟随的时间提示。
7. **两点同步（批量校准）**（启动后访问 **http://localhost:8080**，在右侧「两点同步」面板操作）：
   - 在下拉框中按时间顺序选择两个**未锁定**的锚点片段（锚点 1 需早于锚点 2，锁定片段不会出现在可选项中），并分别输入它们的新开始时间；
   - 由两个锚点的旧、新开始时间确定唯一线性映射 `t′ = k·t + b`，将闭区间 [锚点 1, 锚点 2] 内所有**未锁定**片段的 start/end 一并变换；区间外片段与锁定片段保持不变；
   - 输入的同时，时间轴即以**虚影**（蓝色虚线框，与原片段同泳道）预览校准结果，面板同步显示映射参数与**影响数量**；
   - 出现以下任一情况时「应用校准」被禁用并**列出全部冲突片段**（点击可定位到对应片段），不会部分写入：
     - 新锚点顺序无效（锚点 2 的新开始时间未晚于锚点 1），或锚点本身顺序/状态无效；
     - 变换后任一片段时长低于当前「最小片段时长」，或开始时间早于 `00:00.000`；
     - 校准后区间内及两侧边界的相邻片段不满足当前「相邻片段间隔」。
   - 点击「应用校准」后一次性写入全部结果；「重置」清空锚点选择与输入。
8. **画面布局预览与编辑**：
   - 右侧「画面布局预览」按 16:9 画面显示所选片段的字幕框，并叠加四边各 10% 的安全区（绿色虚线框）；
   - 字幕框位置由 `line` / `position` / `size` / `align` 决定，缺省值遵循 WebVTT 规范（position 50%、size 100%、贴底、居中）；`size` 未显式设置时按估算文本宽度（默认字号 5% 屏高）显示实际占位；
   - 检查器中提供四个布局字段的**独立编辑控件**（`line`/`position`/`size` 文本框、`align` 下拉框），留空即移除该设置；修改这四个字段时，其它未知 cue 设置（如 `vertical:rl`）的原始顺序与内容完全保留；
   - 非法取值（如 `align:middle`、`size:120%`）或字幕框超出 10% 安全区时，会以**警告**形式进入问题清单，点击即可定位到对应片段；只有显式设置了 `line`/`position`/`size` 的片段才做安全区判定；
   - 布局问题不影响导出，仍可按当前内容导出。
9. **精确编辑**：选中片段后在右侧检查器手动输入时间码（支持 `MM:SS.mmm` 与 `HH:MM:SS.mmm`，逗号小数点亦可）、编辑多行文本、cue 设置（`line`/`position`/`align` 等）与标识符，可复制或删除片段。
10. **导出**：点击「导出 WebVTT」下载修复后的 `.vtt` 文件。导出内容为规范 WebVTT：
   - 字幕文本（含多行、内联标签如 `<b>`、时间戳标签）原样保留；
   - cue 设置与 cue 标识符原样保留；
   - 文件头中的 `NOTE` / `STYLE` / `REGION` 块原样写回；
   - 时间戳规范化为 `HH:MM:SS.mmm`（不足 1 小时为 `MM:SS.mmm`）；
   - 锁定状态仅属于编辑器状态，不会写入文件。

> 注意：右侧检查器中的手动时间码输入为**直接设置**（便于精确修正），不会触发跨片段传播；跨片段传播只在时间轴拖动时发生。手动编辑造成的重叠/间隔问题会立即出现在问题清单中，可再用拖动方式修复。

## 项目结构

```
.
├── docker-compose.yml      # 一条命令启动（映射 8080 -> 80）
├── Dockerfile              # 多阶段构建：node 构建 + nginx 静态服务
├── nginx.conf              # SPA 回退配置
├── index.html
├── src
│   ├── App.tsx             # 状态编排与布局
│   ├── lib
│   │   ├── types.ts        # Cue / Settings / Issue / Conflict 类型
│   │   ├── time.ts         # 时间戳解析与格式化
│   │   ├── vtt.ts          # WebVTT 解析与序列化
│   │   ├── solver.ts       # 核心：约束传播求解（锁定/最小时长/间隔/撤销）
│   │   ├── sync.ts         # 两点同步：线性映射批量校准与冲突校验（不部分写入）
│   │   ├── issues.ts       # 问题清单检测（时序 + 布局）
│   │   ├── layout.ts       # 布局设置解析/校验/回写、字幕框几何与安全区检测
│   │   └── sample.ts       # 内置示例字幕
│   ├── components
│   │   ├── Timeline.tsx    # 时间轴：泳道、拖动、冲突标注、缩放、两点同步虚影预览
│   │   ├── CueList.tsx     # 片段列表
│   │   ├── Inspector.tsx   # 片段检查器（含四个布局字段的独立编辑控件）
│   │   ├── SyncPanel.tsx   # 两点同步面板（锚点选择、新开始时间、冲突列表、应用）
│   │   ├── LayoutPreview.tsx # 16:9 画面布局预览（字幕框 + 10% 安全区）
│   │   ├── SettingsPanel.tsx
│   │   ├── IssuesPanel.tsx
│   │   ├── TimeCodeInput.tsx
│   │   └── ImportModal.tsx
│   └── main.tsx
└── scripts/sanity-test.ts  # 核心逻辑测试（npm test）
└── README.md
```
